# Spare Parts Integration

Приложение для автоматической интеграции CMS, PostgreSQL и Report API с использованием Apache Camel.

Приложение получает данные о запчастях из CMS, сохраняет их в исторической базе данных и периодически отправляет сформированный CSV-отчёт во внешний API.

## Возможности

- Получение данных из CMS с поддержкой постраничной загрузки.
- Авторизация в CMS с использованием Basic Auth.
- Сохранение и обновление записей в PostgreSQL по уникальному коду запчасти.
- Сохранение ранее полученных записей, даже если они больше не присутствуют в CMS.
- Получение и кеширование токена авторизации Report API.
- Формирование CSV-файла и отправка его во внешний API.
- Автоматический запуск интеграции каждые 30 минут.
- Обработка результатов синхронизации.

## Принцип работы

1. Планировщик запускает интеграцию каждые 30 минут.
2. Приложение запрашивает данные CMS постранично, по 10 записей.
3. Полученные записи сохраняются в PostgreSQL. При совпадении `spare_code` существующая запись обновляется, при отсутствии создаётся новая.
4. Записи, которые перестали поступать из CMS, не удаляются из базы.
5. Из PostgreSQL формируется CSV-файл.
6. Приложение получает действующий токен авторизации или запрашивает новый.
7. CSV отправляется в Report API.
8. Ответ API обрабатывается и записывается в лог.

## Формат CSV

Файл формируется в кодировке UTF-8, с разделителем `;`, без заголовка.

Порядок полей:

```text
spare_code;
spare_name;
spare_description;
spare_type;
spare_status;
price;
quantity;
updated_at
```

Пример записи:

```csv
SPARE-1;Spare Part 1;Description for spare part 1;BRAKE;RESERVED;22;29;2025-09-09T14:53:45.751668
```

Исходная точность поля `updated_at` сохраняется при передаче данных между системами. В приложении используется `LocalDateTime`, а в PostgreSQL дата хранится в текстовом представлении, чтобы не терять наносекундную точность исходного значения.

## Настройка

Для подключения к внешним API используются переменные окружения.

| Переменная | Описание |
|---|---|
| `CMS_BASE_URL` | Адрес CMS API |
| `CMS_USERNAME` | Имя пользователя |
| `CMS_PASSWORD` | Пароль |
| `AUTH_BASE_URL` | Адрес API авторизации |
| `REPORT_BASE_URL` | Адрес Report API |

Учётные данные не хранятся в исходном коде и должны передаваться через переменные окружения.

## Запуск PostgreSQL

Для запуска базы данных используется Podman Compose.

```bash
podman-compose up -d
```

Параметры подключения:

| Параметр | Значение |
|---|---|
| Database | `integration` |
| Username | `integration` |
| Password | `integration` |
| Port | `5432` |

## Запуск приложения

Перед запуском необходимо:

1. Запустить PostgreSQL.
2. Настроить переменные окружения.
3. Собрать и запустить Kotlin-приложение.

## Логирование

Приложение записывает основные события интеграции:

- начало и завершение цикла;
- количество загруженных страниц и записей;
- формирование CSV;
- получение токена авторизации;
- результат отправки отчёта;
- ошибки взаимодействия с внешними системами и базой данных.

Токены авторизации и полное содержимое CSV в логах не выводятся.
